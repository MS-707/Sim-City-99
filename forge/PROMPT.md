# FORGE — the master prompt

An engine-parameterized build prompt that drives a project from nothing to **shippable**.
Not to a demo. Not to a screenshot-optimized vertical slice.

## The one invariant

> Build the verification harness before anything else.
> Every claim about the artifact is verified against captured evidence — never against your
> assumption about what the code does.

That second sentence names the specific failure mode of a strong coding model: substituting
reasoning-about-source for observation-of-output. It is the only sentence in this document that
may never be edited.

One piece of exhortation survives, because it corrects a real default (models stop at
first-run-success): **working is the floor, not the goal.** Every other motivational phrase has
been deleted. Ambition belongs in the planning input, where it shapes how demanding the rubric
is — not in build instructions, where it only inflates self-report.

## 1. Slots

`/forge:goal` fills these before any autonomous work begins. A slot left at its default is a
decision made by accident.

| Slot | Meaning | A good value looks like | What breaks if wrong |
|---|---|---|---|
| `{{PROJECT}}` | One sentence: what the player does, and for how long | "Five-minute stealth runs through a hand-built noir apartment block" | Scope drifts; nobody can tell when it is done |
| `{{ENGINE}}` | Target engine + harness adapter id | `web` \| `unity` | Wrong adapter ⇒ no capture ⇒ no verification ⇒ every visual claim is unfounded |
| `{{GENRE}}` | Genre and camera model | "2.5D side-scroller, fixed orthographic" | Rubric rows fire that do not apply; real axes go ungated |
| `{{STYLE_BRIEF}}` | The art direction, in observable terms | "Hard-edged shadows, two-value lighting, one warm accent against cool neutrals" | The critic has no external referent and drifts to its own taste |
| `{{ASSET_POLICY}}` | What may be imported vs generated | See §Asset policy below | Critic flags engine defaults as violations and poisons the defect list |
| `{{PERF_BUDGET}}` | Frametime + draw call + memory ceilings | "p95 ≤ 13.9ms, ≤ 900 draws, ≤ 1.2GB" | "Performance" becomes an opinion instead of a gate |
| `{{MIN_SPEC}}` | The *worst* machine that must run it | "2019 quad-core laptop, integrated GPU, 1080p" | You ship something that runs only on the dev machine |
| `{{TARGET_PLATFORMS}}` | Where it must run and how it is delivered | "Desktop browser (Chrome/Firefox/Safari), itch.io" | Platform-specific hardening is discovered at the end |
| `{{SESSION_SHAPE}}` | Length and structure of one play session | "3 levels, ~6 min, restart on death" | Telemetry has no reference session to measure |
| `{{CONTENT_SCOPE}}` | Breadth required for content-complete | "8 levels, 3 difficulty tiers, 1 tutorial" | The project stalls at one beautiful level forever |
| `{{ACCESSIBILITY_FLOOR}}` | Non-negotiable accessibility minimums | See rubric axis `experience` | Ships unplayable for a real fraction of players |

**Asset policy** must be phrased so it cannot indict the engine itself:

> No third-party art, audio, or model assets. Official engine packages are permitted
> infrastructure. Every mesh, texture, material and sound *the player perceives* is generated by
> code in this repo.

## 2. Phases

Serial unless marked parallel. A phase may not start until its entry precondition holds.

### Phase 0 · DIRECTION — human-gated, no code
**Owner:** human + `/forge:goal` · **Entry:** none · **Parallel:** no

Emits, and nothing downstream may rewrite them:
- `rubric.yaml` — the standard (see `RUBRIC.md`)
- `capture-spec.json` — determinism + the enumerated evidence set (see `templates/capture-spec.json`)
- `technique-ledger.md` — technique → observable property → naive failure → cheap fallback
- `non-goals.md` — so a critic cannot invent new axes forever
- `architecture-contract.md` — the write-set partition table

**Exit gate:** human signs off; the rubric's git hash is recorded. `/forge:goal` is marked
`disable-model-invocation` — a builder can never rewrite its own grading standard. That means
Phase 0 is run by a person, before the autonomous run. This is a workflow requirement, not a
limitation.

> **The technique-leak rule.** Planning asks: *"for this style and engine, what are the three
> techniques a practitioner would use that a naive implementer would not, and what observable
> property does each buy?"* Only column two ever reaches a critic. A critic told about
> inverted-hull outlines checks whether inverted hulls are *present*, instead of whether the
> silhouette *reads at distance*. Compliance silently substitutes for quality.

### Phase 1 · CONTRACT — the walking skeleton
**Owner:** `agents/crew/architect.md` · **Entry:** Phase 0 signed off · **Parallel:** no

"Define a shared architecture first" names no artifact, so N readers interpret it divergently and
it surfaces at integration as a rewrite. Replace it with a **compiled green build**: everything
stubbed, every interface exporting its agreed signature, the app boots, the harness captures a
gray frame.

Emits the partition table — `subsystem | owned globs | forbidden globs | public interface | budget
line | grading seat`. Globs must be **disjoint**, partitioned by *write set*, never by domain
vocabulary.

**Exit gate:** build green, skeleton boots, gray frame captured.
**Rule:** fan out from a green build, never from a document.

### Phase 2 · HARNESS — before any feature work
**Owner:** `agents/crew/harness-engineer.md` (sole owner) · **Entry:** Phase 1 green · **Parallel:** no

Four capabilities:

| Capability | What it does |
|---|---|
| CAPTURE | Deterministic frames per `capture-spec.json`; contact sheets; temporal diff maps |
| DRIVE | Tick-indexed input tapes. Never wall-clock sleeps |
| MEASURE | Frametime p50/p95/p99 + long-frame count (**never mean FPS**), draw calls, memory, boot time, input-to-visible latency, offline audio buffers |
| LINT | Asset policy, glob boundaries, and one grep that **fails the build if any code path branches on a headless/capture/screenshot flag** |

**Exit gate — the determinism self-test:** capture the same moment twice, require identity within
tolerance. Until it is green the harness **refuses to emit any visual verdict**. Without
determinism, "fixed" and "regressed" are unevaluable, and the loop is a random walk emitting
progress-shaped text.

The harness is **version-locked** for the duration of a convergence run. A changed instrument
invalidates the entire comparison series.

### Phase 3 · BUILD WAVES — parallel
**Owner:** crew · **Entry:** harness green · **Parallel:** yes, capped at 3–4 concurrent writers

Each writer works in its own git worktree on strictly disjoint globs. On a shared filesystem,
concurrent writers do not produce merge conflicts — they produce **lost writes**, because git's
conflict machinery never engages when there is never a second commit. Silent, and the most likely
real-world failure.

Each brief carries: owned globs, forbidden globs, **budget line**, rubric-row slice, capture
moments to produce, acceptance check, timeout, abort behavior (revert to stub, coordinator takes
over).

> **Performance is a gate, never an agent.** It is an invariant over everyone else's code. As a
> peer agent it either does nothing all wave, or arrives at merge time and rewrites six agents'
> work — invalidating every critic verdict already paid for. Every builder carries a budget line
> instead.

### Phase 4 · CONVERGE — per subsystem, per milestone
**Owner:** `/forge:converge` · **Entry:** wave merged, build green · **Parallel:** critique only

See §4 for the protocol. Parallelism is spent on the **read-only** axis (N seats, cameras,
moments, profiling runs against one frozen build) — never on the write axis, which is maximally
coupled.

### Phase 5 · CONTENT
**Owner:** `agents/crew/content-engineer.md` + `systems-engineer.md` · **Entry:** alpha reached

Breadth, which the original prompt never requests because it is not photogenic: levels/tracks to
`{{CONTENT_SCOPE}}`, difficulty tiers, progression, onboarding, pause, settings, rebindable input,
save/load, results persistence.

**Feel and balance are resolved here, by shortlist — not by judgment.** No agent judges game feel
and no rubric closes it. Run N parameter configs, measure outcome variance / failure rate /
time-at-extremes, auto-reject the broken, hand the human **5 candidates**. This converts unbounded
aesthetic tuning into a bounded *selection* problem. Same technique for difficulty and AI
rubber-banding.

### Phase 6 · HARDEN
**Owner:** `agents/crew/hardening-engineer.md` · **Entry:** content complete

Window resize, focus loss, graphics-context loss, device change, boot time, error recovery,
min-spec performance and quality tiers — and the **accessibility floor**: colorblind-safe palette
verification, motion/shake toggle, remappable input, text scale, audio-cue redundancy.

The original prompt is actively hostile here: it mandates a high-saturation palette with no
colorblind check, and mandatory screenshake with no toggle.

### Phase 7 · SHIP GATE
**Owner:** `/forge:ship` + the five-seat council · **Entry:** beta reached

See `COUNCIL.md`. No agent may claim *shipped*, *done*, or *complete* without a council record id.

## 3. The milestone ladder

Gates measure **counts**, not screenshots.

| Milestone | What it measures |
|---|---|
| prototype | Skeleton compiles green; harness determinism self-test passes |
| vertical slice | One representative segment; all `milestone_scope: slice` rows PASS |
| alpha | All systems present; zero open BLOCKERs; `scope: alpha` rows PASS |
| content complete | `{{CONTENT_SCOPE}}` met; onboarding present; difficulty tiers exist |
| beta | Feature freeze; bug burn-down; MAJOR count ≤ ceiling; replay suite green |
| RC | Zero blockers; crash-free rate ≥ threshold **on `{{MIN_SPEC}}`**; perf budget met on min spec |
| gold | Full ship gate passed with a council record id + human sign-off rows |

## 4. Evidence channels

The harness stops being a camera. Each channel with what it **cannot** see:

| Channel | Sees | Cannot see |
|---|---|---|
| Still frame | Composition, value, contrast, colour, silhouette, material read | Anything temporal; anything about feel |
| Contact sheet (burst at fixed dt) | Animation phrasing, transitions, pacing | Sub-frame timing; input response |
| Temporal diff map (per-pixel delta between consecutive frames, rendered as an image) | Crawl, shimmer, popping, seams — makes temporal noise visible as *spatial structure* to a still-frame judge | Whether the motion is *good*, only whether it is *stable* |
| Full-session replay (fixed input tape, end to end, asserted identical every run) | Crashes, state corruption, progression breaks, determinism drift | Aesthetics |
| Telemetry | Frametime distribution, draw calls, memory, boot time, input-to-visible latency, outcome spread, session-completion rate | Anything visual |
| Offline audio buffer | Mix balance, clipping, silence, missing cues | Whether it sounds *good* |

**Stills cannot see feel.** Nothing in this list closes feel. Feel is resolved by
shortlist-selection with a human (Phase 5). Any document claiming otherwise is lying.

## 5. Convergence protocol

Per pass:

1. **Capture** the spec'd set into `evidence/pass-N/` with a manifest recording commit sha, seed,
   tick, camera. Captures are comparable only within a base sha; the ledger records it and
   **refuses cross-base comparisons**.
2. **Automated gates run first.** Telemetry thresholds, golden-frame diffs, lints. Any failure
   files defects and **skips the council entirely**. Roughly half of what a critic is asked to
   intuit is a threshold check in a costume — never spend judge tokens aesthetically evaluating an
   artifact that already fails a numeric bar.
3. **Council seats** run in forked context, read-only allowlist, receiving evidence + their rubric
   rows + prior ledger. Never source, technique names, builder rationale, prior transcripts, or
   the pass number.
4. **Builder fixes** BLOCKERs, then MAJORs. Minors never gate a loop; they batch to polish.
5. **Verify each claimed fix** by an order-swapped A/B at identical tick and camera against the
   previous accepted artifact.
6. **Append to ledger.** Promote accepted captures to goldens.

### Exit predicate

Converged when **all** hold:
- every in-scope rubric row **affirmed PASS** with an evidence reference
- zero open defects at severity ≥ major
- goldens show no regression on out-of-scope rows
- telemetry within budget

Because exit requires *positive per-row affirmation*, **"the critic ran quiet" is not an exit
path at all.** This replaces "loop until the critic runs out of specific defects to name", which
is a property of the judge's output distribution rather than of the artifact — and which, combined
with an instruction to be harsh, is non-terminating by construction.

### Bounded exits

Each **writes status and continues the program** rather than stalling it:
- round cap reached (6 per subsystem per milestone)
- any defect id reopens twice → oscillation; freeze and escalate
- budget exhausted

Budget exhaustion is a **first-class, non-shameful outcome**, and it is the mechanism that finally
makes *"it's at 70% and here's why"* honest. Attainment is arithmetic performed by the driver over
ledger rows — weighted passing ÷ total applicable — never a number asked of the builder
(motivated) or the critic (variance).

## 6. What this prompt refuses to claim

Two things this machinery **cannot determine**, and no rubric, telemetry channel, or council seat
closes either:

1. **Whether it is fun.**
2. **Art-direction cohesion at content scale** — the composed-frame problem, multiplied by breadth.

Both require human time, and both have dedicated sign-off rows in the ship gate that the council
is structurally forbidden from granting. The machinery's job is narrower and worth stating
plainly: to ensure that when the human finally sits down to play it, they are judging *fun* rather
than tripping over bugs.
